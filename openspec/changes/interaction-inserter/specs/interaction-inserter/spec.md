## 新增需求

### 需求:打开互动工作台
系统必须提供一个脚本按钮，用于打开互动插入器的全宽工作台。

#### 场景:通过脚本按钮打开
- **当** 用户点击脚本按钮“打开互动工作台”
- **那么** 系统显示全宽互动工作台

#### 场景:关闭工作台
- **当** 用户在工作台中点击关闭
- **那么** 系统隐藏工作台且不得删除已保存的聊天变量互动状态

### 需求:提供三种互动模式
系统必须支持当下场景、一对一、远程通信三种互动模式。

#### 场景:当下场景零配置
- **当** 用户选择当下场景模式
- **那么** 系统不得要求用户选择角色或输入额外场景信息

#### 场景:一对一选择角色
- **当** 用户选择一对一模式
- **那么** 系统必须允许用户从角色列表选择一个角色标识

#### 场景:远程通信复用角色列表
- **当** 用户选择远程通信模式
- **那么** 系统必须允许用户从同一角色列表选择一个角色标识

### 需求:维护极简角色列表
系统必须允许用户维护一个可复用角色列表，每个角色只保存一个用户输入的角色名或身份标识。

#### 场景:添加角色标识
- **当** 用户输入角色标识并确认添加
- **那么** 系统将该标识加入当前聊天的角色列表

#### 场景:复用角色标识
- **当** 用户在一对一或远程通信模式中创建互动
- **那么** 系统可以复用已经添加过的角色标识

### 需求:独立生成互动回复
系统必须使用独立生成请求产生互动回复，不得创建主聊天楼层。

#### 场景:发送互动输入
- **当** 用户在互动工作台中发送一条输入
- **那么** 系统使用配置的 API、通用互动约束、当前模式提示词、互动历史和用户输入发起生成请求

#### 场景:不创建主聊天楼层
- **当** 互动回复生成完成
- **那么** 系统不得向主聊天创建新的用户楼层、AI 楼层或隐藏楼层

#### 场景:流式显示
- **当** 当前设置启用流式显示且生成请求返回流式事件
- **那么** 系统在当前会话中逐步更新对应 AI 回复

### 需求:保存互动状态
系统必须将角色列表、互动会话、互动消息和当前会话标识保存到当前聊天变量。

#### 场景:保存互动消息
- **当** 用户输入或 AI 回复产生
- **那么** 系统将该消息追加到当前会话并写入聊天变量

#### 场景:切换聊天隔离状态
- **当** 用户切换到另一个聊天文件
- **那么** 系统读取该聊天文件自己的互动状态，不得复用前一个聊天文件的互动消息

### 需求:配置核心设置
系统必须提供设置页配置聊天 API、三种模式提示词和世界书插入模板。

#### 场景:配置自定义 API
- **当** 用户选择自定义 API 并填写 API URL、Key、模型和 source
- **那么** 系统在后续互动生成中使用这些配置作为 `custom_api`

#### 场景:配置模式提示词
- **当** 用户修改当下场景、一对一或远程通信的模式提示词
- **那么** 系统在对应模式的后续生成请求中使用修改后的提示词

#### 场景:配置世界书插入模板
- **当** 用户修改世界书插入模板
- **那么** 系统在后续合并时使用该模板包裹未合并互动原文

### 需求:合并互动到世界书
系统必须将未合并互动原文全量写入固定世界书条目“本轮互动内容”。

#### 场景:合并并退出
- **当** 用户点击合并并退出
- **那么** 系统将未合并互动原文套入世界书插入模板，并写入固定世界书条目“本轮互动内容”

#### 场景:固定世界书策略
- **当** 系统写入“本轮互动内容”条目
- **那么** 该条目必须以内置固定策略 constant / system / depth 1 写入，且用户不得在第一版配置条目名称、身份或深度

#### 场景:合并后清空互动记录
- **当** 合并成功且设置启用合并后清空
- **那么** 系统清空当前聊天变量中的已合并互动消息

### 需求:清空固定世界书条目
系统必须支持清空固定世界书条目，避免旧互动持续影响后续主剧情。

#### 场景:手动清空
- **当** 用户点击清空
- **那么** 系统清空当前聊天中的未合并互动记录或固定世界书条目

#### 场景:新楼层后清空
- **当** 检测到新的主聊天楼层生成完成且设置启用自动清空
- **那么** 系统清空固定世界书条目“本轮互动内容”

#### 场景:重 roll 后清空
- **当** 检测到主聊天消息被 swipe 或重新生成且设置启用自动清空
- **那么** 系统清空固定世界书条目“本轮互动内容”

### 需求:提供发布用导入 JSON
系统必须在导入到酒馆目录中提供发布用导入 JSON，用于分发时导入酒馆。

#### 场景:发布导入文件使用线上构建产物
- **当** 用户导入发布版 JSON
- **那么** 脚本内容必须通过 `https://testingcf.jsdelivr.net/gh` 加载已构建的互动插入器脚本

#### 场景:发布导入文件不依赖本地实时修改服务
- **当** 检查发布版 JSON 的脚本内容
- **那么** 该内容不得引用 `localhost`
