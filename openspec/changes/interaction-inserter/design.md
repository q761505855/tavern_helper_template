## 上下文

本项目用于编写 Tavern Helper 支持的脚本或前端界面。该变更面向故事生成型角色卡：主聊天继续承担长段剧情生成，新增脚本工作台承担临时互动生成，并在玩家确认后把互动原文合并回后续剧情上下文。

第一版设计刻意保持极简：不要求主剧情 AI 自动输出可交互状态，不维护场景描述或人物档案，不做合并前摘要。玩家只维护一个角色标识列表；当下场景模式无需任何额外输入。

## 目标 / 非目标

**目标：**
- 通过脚本自带按钮打开一个全宽互动工作台。
- 支持当下场景、一对一、远程通信三种互动模式。
- 支持极简角色列表，一对一和远程通信复用同一列表。
- 通过 `generateRaw` 发起独立互动请求，支持流式显示。
- 将互动消息保存在聊天变量，不创建主聊天楼层。
- 将未合并互动原文套入世界书插入模板，写入固定世界书条目。
- 提供设置页配置聊天 API、三种模式提示词、世界书插入模板和必要辅助项。

**非目标：**
- 不实现聊天栏左侧扩展菜单入口优化。
- 不实现 AI 自动识别可交互人物、自动维护场景或自动总结。
- 不实现人物档案、场景档案或复杂会话知识库。
- 不实现合并前摘要整理。
- 不修改主聊天楼层内容或创建隐藏互动楼层。

## 决策

### 使用脚本项目而不是前端界面项目

工作台需要由脚本按钮打开，并覆盖/挂载到 SillyTavern 页面中，而不是依附某个消息楼层渲染。脚本项目可以使用 `appendInexistentScriptButtons` 和脚本 DOM 挂载能力，适合作为第一版入口。

替代方案是创建消息楼层前端界面，但它需要依赖某个楼层存在，也不适合作为全局互动工作台入口。

### 使用全宽工作台而不是侧边抽屉

玩家在互动过程中不需要看主剧情原文，选择全宽布局可以把空间留给对话流。主界面只保留左侧模式/角色列表、右侧宽对话区和底部操作按钮。

替代方案是侧边抽屉或浮窗，它们更轻，但对长对话显示不够舒适。

### 极简角色列表

一对一和远程通信只保存用户输入的角色标识，例如“艾琳”或“旅店侍女艾琳”。AI 通过主聊天上下文、角色卡和世界书自行匹配人物。

替代方案是维护角色档案或场景档案，但第一版会增加输入负担，也容易偏离验证核心体验的目标。

### 聊天变量保存互动状态，脚本变量保存设置

互动记录和角色列表与当前聊天文件相关，因此存入聊天变量。API、提示词和模板设置属于插件配置，存入脚本变量。

这种分层避免不同聊天之间共享互动记录，同时允许同一个插件配置跨聊天复用。

### 使用 `generateRaw` 和自定义 ordered prompts

互动模式需要不同于主剧情模式的提示词结构。`generateRaw` 可通过 `ordered_prompts` 明确组合角色设定、世界书、通用互动约束、模式提示词、互动历史和用户输入，并可通过 `custom_api` 支持当前 API、proxy preset 或自定义 API。

替代方案是使用 `generate` 和当前预设，但它更容易继承主剧情预设中过强的长段叙事倾向。

### 固定世界书条目，仅暴露插入模板

合并目标固定为“本轮互动内容”，内部固定为 constant / system / depth 1。用户只配置插入模板。这样设置页更简单，也减少错误配置导致合并失效的风险。

替代方案是暴露条目名、身份、深度等配置，但第一版不需要这种灵活性。

## 风险 / 权衡

- **角色标识匹配不准确** → 提示词必须说明角色标识来自玩家输入，AI 必须根据当前剧情上下文匹配，无法确认时应自然询问或保守回应。
- **全量合并过长** → 第一版接受该限制，并提供清空/复制操作；后续版本再添加 AI 摘要整理。
- **世界书条目残留影响后续剧情** → 在新楼层、重 roll 或用户手动清空时清空固定条目。
- **自定义 API 配置错误** → 设置页保留当前酒馆 API 作为默认路径，并允许用户恢复默认。
- **流式事件串扰** → 每次生成必须使用唯一 `generation_id`，流式监听只更新对应会话。

## 迁移计划

这是新增脚本功能，不需要迁移现有数据。首次加载时若脚本变量或聊天变量不存在，使用默认设置和空状态初始化。

回滚方式是禁用或移除该 Tavern Helper 脚本；已写入的“本轮互动内容”世界书条目可通过清空按钮或手动删除清理。

## 待定问题

- 第一版脚本目录名称在实现阶段确定。
- 默认提示词文本可在实现阶段基于当前设计进一步打磨。
- 固定世界书条目应优先写入聊天世界书；若当前聊天没有世界书，实现阶段需要确认是自动创建聊天世界书还是回退到角色卡世界书。
